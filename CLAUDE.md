# Hyprland config

Multi-machine Hyprland configuration, in Lua. `hyprland.lua` is only `require`
lines; everything lives under `conf/*.lua`. hypridle, hyprlock, and hyprsunset
have no Lua config and stay hyprlang `.conf`.

## Architecture

- `conf/machine` is a **gitignored symlink** to `conf/machines/<hostname>/`,
  created once per machine (`ln -s machines/<host> conf/machine`). Shared config
  (`appearance.lua`, `keybinds.lua`, `rules.lua`) applies everywhere;
  per-machine dirs hold `monitors`, `env`, `programs`, `autostart`, `input`,
  extra keybinds, and `hyprlock`/`hypridle` configs.
- Machines: **zion** — desktop, DP-3 (1080p@165, no VRR: panels aren't capable) +
  HDMI-A-1 (1080p@75), eww clock/workspace widgets. **rocinante** — ThinkPad,
  eDP-1, touchpad gestures, keyboard-backlight binds.
- Session: launched via `start-hyprland` (not uwsm). Long-running daemons are
  **systemd user units** under `graphical-session.target`, pulled up by
  `hyprland-session.target` from autostart — see `docs/systemd-session.md`.
  Custom units live in `systemd/` (repo is source of truth; enabled by
  absolute path). New machine setup: `scripts/setup-session-services`.
  Failing units end in `failed` and are reported (start limits + `RestartMode=direct` +
  `OnFailure=unit-failed-notify@%n.service`, hourly `failed-units-check.timer`; journal and a marker in
  `~/.local/state/unit-failed/` first, the toast is best effort) — see `docs/systemd-session.md`.
- Session exit goes through `scripts/session-exit` (stops the session target,
  then `hyprctl dispatch exit`). Never bind bare `hyprctl dispatch exit`.
- XWayland is disabled globally.
- The last thing `hyprland.lua` does is `dofile` `~/.cache/wallust/hypr-theme.lua`
  if it exists: per-colorscheme blur overrides generated by the wallust `theme`
  script from the scheme JSON (see `~/.config/wallust/docs/CLAUDE.md`). If blur values
  don't match `conf/appearance.lua`, check that file before debugging here.

## Locking (lock / idle / power submap)

One entry point: `scripts/lockscreen` (read its header before touching any of this).
- `lockscreen lock`: hypridle's `lock_cmd`. Everything else locks through
  `loginctl lock-session` (power submap L, the idle listener, `before_sleep_cmd`),
  so there's a single path. It's a flock'd supervisor: runs hyprlock, relaunches
  it on any non-zero exit (crash), and on exit 0 (unlocked) turns the displays
  on. Needs `misc:allow_session_lock_restore = true` (appearance.lua).
  **If Hyprland itself crashes**, start-hyprland restarts it `--safe-mode
  --locked`: safe mode ignores our config, so restore is off and every
  relaunch is denied ("we got yeeten", rc=1). `relock_prep` follows the new
  instance signature and sets the option via `hyprctl eval` before each
  relaunch (2026-11-05: looped 3h behind the lockdead screen until a reboot).
  It also sets `key_press_enables_dpms` (safe mode leaves it false: dark
  displays could not be woken by any key after the 2026-11-06 17:43 crash)
  and runs `scripts/hypr-crash-logs`. Safe mode still has none of our binds
  (F1-F4, Enter); log out and back in to get the config back.
  **The supervisor runs in its own `systemd-run --scope`**: hypridle aborts
  seconds after a Hyprland crash, and systemd killed its cgroup with the
  supervisor and the relaunched hyprlock in it (2026-11-06 08:18, 16:52,
  17:43: locked with nothing to unlock). Falls back to locking in place.
  **Children must not inherit the lock fd** (`9>&-`): `rbw lock` once started
  rbw-agent, which held the flock forever, and every later lock became a
  silent no-op.
- Fingerprint is **Enter-triggered and not hyprlock's** (the user wants no
  scan until they press Enter): `LOCKSCREEN_ENTER` in conf/keybinds.lua is a
  locked, non-consuming Enter bind that stays *disabled* except while locked,
  and only on machines with fprintd (the script flips it with
  `hyprctl eval 'LOCKSCREEN_ENTER:set_enabled(..)'`).
  It runs `lockscreen fprint`: one `fprintd-verify`, and on a match
  `pkill -USR1 hyprlock` (hyprlock's unlock signal). No status text (the user
  wants only the clock); the only feedback is the reader's LED.
  hyprlock's own `auth:fingerprint` stays disabled: it scans from the moment
  it locks and never retries after a device error.
- `lockscreen away`: power submap A, or F4 on the lock screen. A
  `sleep:handle-lid-switch` block inhibitor around `lockscreen away-hold`,
  which waits for the lock to be taken and then released (it locks only if
  not already locked), so it works from the desktop and from the lock screen.
  Displays off, except on NVIDIA (zion: see "No DPMS off" below). The lid
  does NOT suspend while away (the user chose this). The block inhibitor also
  stops hypridle's 15-min `systemctl suspend` (logind
  answers `inhibited`; verified 2026-10-18). Away also starts
  `scripts/hotspot-handoff`: it rescans for up to 2 min and switches wifi to the
  phone's `hotspot` profile as soon as it is visible (no-op at home / without
  the profile). The profile is `802-11-wireless.hidden=yes` so NM probes for it
  directly. The handoff runs with fd 7 closed: when away comes from F4, fd 7 is
  `power`'s one-action lock, and holding it would silently refuse F1-F3 for 2 min.
- ly-style power keys on the lock screen, both machines: F1 poweroff, F2
  reboot, F3 suspend (ends away first: its inhibitor would block it), F4
  away. `LOCKSCREEN_POWER(on)` in conf/keybinds.lua, armed with
  LOCKSCREEN_ENTER for the lock's lifetime (disarmed by an EXIT trap,
  re-armed on `config.reloaded` via `lockscreen rearm`); `lockscreen power`
  also refuses unless hyprlock is up. **Wake guard:** the press that wakes
  dark displays (`key_press_enables_dpms`) can also fire the bind (order
  unverified: `wtype` input doesn't trigger binds), so a 100ms timer
  records when a display was last off and F-presses within ~300ms of that
  only wake. Panels `scripts/ddc-power` switched off count as dark (its state
  file `$XDG_RUNTIME_DIR/ddc-power.off` is non-empty until the wake is
  verified, ~5s): Hyprland reports them as on, and the waking press would
  otherwise power off. Lock state is read from `/proc/locks` (`locked()`), never by
  probing with flock (a probe briefly holds the lock and would no-op a
  concurrent lock_cmd); the PID there is the `flock` helper's, not the
  supervisor's, so don't wait on it. On rocinante F1-F4 are media keys
  unless Fn-lock is on.
- `lockscreen resume`: `after_sleep_cmd`. Displays on: DDC (`scripts/ddc-power
  on`, no-op unless hypridle turned them off) and DPMS, re-sent for 5s while
  any output reports `dpmsStatus: 0` (the outputs drop and come back ~1s after
  resume, so one early dpms on can be lost).
- Speed: the laptop background is `grim -l 0` (uncompressed PNG, ~50ms; the
  default compression level took ~1.25s) and hyprlock `animations` are off.
  Keep slow calls (e.g. `fprintd-list`, ~460ms) out of the lock and Enter paths.
- PAM (both machines): hyprlock uses `/etc/pam.d/hyprlock-nofp` (outside the
  repo, installed by hand), pam_unix only. **Never add pam_faillock or
  pam_fprintd there, and never point hyprlock back at the default service**
  (it chains to system-auth's faillock). Any auth that abandons hyprlock's
  pending PAM conversation (fingerprint, SIGUSR1) makes faillock count a
  failure; 3 fingerprint unlocks within 15 min locked the user out on rocinante
  (2026-09-25), and Enter presses on a black post-resume screen did the same on
  zion, tty login included (2026-09-26). Rate limiting is hyprlock's
  `general:fail_timeout`; both machines set `ignore_empty_input`. A missing
  PAM service falls back to `/etc/pam.d/other` (pam_deny) = can never unlock,
  so install the PAM file before a config references it.
- rocinante's lock screen deliberately has no input-field (the user's choice):
  type the password blind + Enter. `ignore_empty_input` stops Enter-to-wake
  counting as an attempt.
- Idle (rocinante): 4:30 dim → 4:45 notify → 5:00 lock → 15:00 suspend.
  Idle (zion): 14:30 notify → 15:00 lock → 20:00 screens off (DDC) → 30:00
  suspend.
- **No DPMS off while locked on NVIDIA (zion).** Hyprland 0.57.x +
  aquamarine 0.16 exits uncleanly ~0.5-1.3s after a DPMS change while hyprlock
  holds the lock: no core dump, no crash report, and start-hyprland says
  "exit not-cleanly" and restarts it in safe mode. Triggers seen: DPMS off
  (`lockscreen away`, hypridle; 2026-11-05 09:18 and 18:03, 2026-11-06 08:18
  and 16:52) and the DPMS on after a resume (2026-11-06 17:43). Since the
  2026-11-03 upgrade, 4 of 5 DPMS offs under our config crashed; ~7 DPMS
  off/on in safe mode didn't. Upstream aquamarine#483/#475, omarchy#17872,
  unfixed as of 2026-11-07. So `lockscreen away` skips its `dpms off` where
  `/proc/driver/nvidia` exists (`can_blank`), and zion's hypridle turns the
  screens off over **DDC/CI** instead (`scripts/ddc-power`: the panel powers
  down, the connector stays up, Hyprland sees nothing; Acer GF246 only takes
  D6=05, ASUS VG247Q1A D6=04; both wake on D6=01; verified 2026-11-07).
  Away mode can't use DDC: Hyprland's key-wake doesn't see DDC state and
  hypridle's on-resume only fires after its own timeout, so nothing would
  wake them. relock_prep only recovers *after* a crash. Re-enable DPMS once
  a fixed Hyprland/aquamarine ships.
  **Crash evidence:** Hyprland logs only to `/run/user/$UID/hypr/<sig>/`; a
  dead instance's dir (with `hyprland.lock` left behind; a clean exit
  removes it) survives until reboot. `scripts/hypr-crash-logs` copies those
  logs to `~/.local/state/hypr-crashes/` (run by hypridle's `ExecStartPre`
  drop-in and by relock_prep). Read the newest one before theorising about a
  crash. `~/.local/state/ly-session.log` is start-hyprland's stdout, but ly
  overwrites it at each login.
- **Resume hangs (zion), cause unknown.** 2026-11-05 18:33 and 2026-11-07
  10:40: the journal ends at `PM: suspend entry (deep)` with no `suspend exit`
  and the machine needed a hard reset. Not the lock scripts (one had no crash
  and the screens on). Kernel 7.2.14 + nvidia-open 615.78.08 + the new
  `UseKernelSuspendNotifiers=1` path; no linux-lts installed to compare.

## Gotchas (hard-won, do not relearn)

- **Once `hyprland.lua` is the live config, `hyprctl dispatch <name> <args>`
  (old hyprlang two-token syntax) fails.** `hyprctl dispatch` now expects a
  Lua expression: `hyprctl dispatch 'hl.dsp.<name>(<args>)'` (e.g. `hyprctl
  dispatch 'hl.dsp.exit()'`, `hyprctl dispatch 'hl.dsp.dpms({action = "off"})'`,
  `hyprctl dispatch 'hl.dsp.window.move({ direction = "l" })'`). This bit
  every script that shells out to `hyprctl dispatch` (`session-exit`,
  `movewindow`, `lockscreen`, `window-switcher`, `workspace-send-all`) and
  both `hypridle.conf` files' `dpms on`/`off` actions — hypridle itself
  stays hyprlang, but its shelled-out `hyprctl dispatch` calls are
  interpreted by the *live Hyprland instance*, so they need the new syntax
  regardless of hypridle's own config format. Audit any new script or
  hypridle/hyprlock action that calls `hyprctl dispatch` for this.
- **`hl.dsp.dpms` takes a table: `hl.dsp.dpms({action = "on"})`.** A bare
  string (`hl.dsp.dpms("on")`) is silently ignored and the call *toggles*.
  `hyprctl` still prints `ok`. This blanked the screen right after unlock
  (the old away-mode script) and right after resume (`after_sleep_cmd`) until 2026-09-25.
  Reference: `/usr/share/hypr/hypridle.conf` and `/usr/share/hypr/stubs/hl.meta.lua`.
- **hypridle crashes at startup if `~/.config/hypr/hypridle.conf` is missing,
  even when `-c` points to a valid file** (hypridle 0.1.7). The top-level
  `hypridle.conf` is a tracked symlink to `conf/machine/hypridle.conf` for this
  reason — do not delete it.
- `hyprctl configerrors` only validates the hyprland.lua chain — hypridle,
  hyprlock, and hyprsunset configs are NOT checked. hypridle silently ignores
  unknown options (an invented `inhibitor` block lingered for months unnoticed).
- `dwindle:preserve_split = true` (appearance.lua) is required for
  `togglesplit`/`rotatesplit` to do anything; without it they silently no-op.
- The resize submap is hold-style: HJKL binds carry the SUPER modifier (it's
  still held), and `bindrt` (release + transparent) on W exits — transparent
  is needed so the catchall doesn't shadow the release.
- `hyprctl dispatch exec` parents processes to the session; use it instead of
  plain `&` when starting daemons from a shell.
- When testing binds, `hyprctl keyword bind ...` adds a temporary bind that
  vanishes on the next `hyprctl reload`.

## Workflow

- After config edits: `hyprctl reload && hyprctl configerrors`.
- Inspect live binds with `hyprctl binds -j | jq`.
- Commits: conventional style (`feat:`/`fix:`/`chore:`), one logical change
  each, **always pass explicit pathspecs to `git commit`** — the index may
  hold staged deletions that a bare commit would swallow.
- `KEYBINDS.md` is the human-readable bind reference — any commit that
  changes keybinds must update it in the same commit.
- Remote is `gitea.lan`; push only when asked.
